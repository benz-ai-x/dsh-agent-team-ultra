# Establish an official-first DSH-only baseline

On 2026-09-09 the user authorized B0: retain versioned Digital Employee Profiles,
explicit activation/rollback/archive, official DSH teammate Launch/Binding and a
minimal Studio, while retiring the persistent native adapters, enhanced Team
message/task UI, independent model routing, unified Run evidence and evaluation
promotion machinery. The objective is a smaller supported product on fixed,
unmodified official Harness `5dda764ed3aa172535a7967b06ff95d9cbfe536a`, not
feature-equivalent migration of the former heterogeneous collaboration platform.

## Consequences

- This decision supersedes the conflicting B0 scope in ADRs 0004–0027 and the
  old full-feature project contract; those records and Spec #18/#44 remain
  historical requirements/evidence, not automatic B0 acceptance. Their past
  completion status is not rewritten. Retained authority, immutable Revision,
  CAS, exact-Agent composition and teardown guarantees still apply.
- Official Team/Session own roster, messages, tasks, continuation and execution.
  B0 uses their public interfaces and records actual DSH child identity rather
  than promising an independently selected model. Official native one-shot
  providers are not B0 durable teammates.
- B0 owns an isolated data identity and installation. No old Session/Ultra/native
  dataset is opened, downgraded, silently filtered or automatically imported.
  Keep the matching old program/source and original data. Future Profile import
  is a separate explicit operation that validates unsupported policies and
  creates unactivated definitions; it cannot erase old evaluation requirements.
- `f84584def627b4af78a029af8788de73da0ad567` and maintained Harness
  `3c38b1d4e8bf219750203e44b1df033ced754e92` identify the retained old baseline.
  Existing uncommitted research and the provided official checkout's changes
  remain untouched. Local B0 work does not authorize publishing or deletion of
  historical repositories, worktrees, credentials or application data.
- Each retained behavior needs public-interface tests. Final support requires
  the fixed-source build, generated protocol, actual package closure, installed
  Web smoke, data rejection/recovery and complete disposal checks. Removing a
  feature removes its dedicated tests only after its callers and declarations
  have also left the shipped product; foundational safety gates stay.
