# 0001: Local overlay and sidecar state

Status: accepted — 2026-08-30

## Decision

Ship Agent Team Ultra as a local-only overlay against the audited Harness
checkout. Consume the existing `agentTeams` contract rather than fork or
replace it. Store profile and binding records in a plugin-owned
`storageDomain`; do not add external custom Session event types.

## Why

The experimental Agent Team family is private and excluded from release, so an
external npm package cannot have an installable dependency closure today. The
stock persistence runtime also has a closed generated Session event catalog.
Sidecar storage gives Ultra durable, versioned state without corrupting Agent
Team replay or pretending type augmentation registers a durable event.

## Consequences

The source-linked profile is runnable and testable on the pinned commit but is
not publishable. Agent Team retains authority over roster, mailbox, tasks,
recovery, and child teardown. Ultra owns profile CAS, the pre-provision binding
commit, and child-scope capability installation. Promotion requires the
upstream Agent Team packages to become published or Ultra to independently
reimplement their public contracts.

The local delivery check creates six archives: three Ultra packages and the
three pinned private Agent Team packages. Those archives prove package content
and browser-safe ordinary resolution, but they are not advertised as an
independent executable closure: the pinned public DSH peer versions are not all
available in the registry. The runnable Web profile installs the same six built
packages through explicit `link:` specs, so Node resolves their public runtime
peers from the audited Harness and Ultra workspaces. The bundle keeps the five
runtime packages as optional peers so it can act as this local composition
layer without requesting nonexistent registry packages.

Typert artifacts are generated by the official pinned generator in an isolated
temporary analysis workspace, because an out-of-tree private package is not a
public owner in the Harness workspace generator. The Web factory uses an
external compatibility bundle preset with the same platform boundary and
generated-Remote purity rule; it does not import unpublished Harness build
internals.
